我正在经营一个 AI 实践社群，希望和大家一起把 AI 变成真正可使用、可创造的新能力。

上周coffee chat约到一个在美国做 AI consulting 的朋友，他副业做了几年自动化咨询，年收入已经跑到了几十万刀。

我很好奇，全网都在卖 agent，为什么他能做这么好。

他说，钱基本不在 agent 上，在 data plumbing。

一时之间有两种情绪在交织，自己闷声赚钱路子被公之于众的不快和找到知音的舒适。

是的，很多客户嘴上说想要 agent，实际上连 data infrastructure 都是从零开始。

我接触的中小企业，几乎有同一个问题：想用 AI，但生成出来的东西过于泛化，跟业务完全不搭。要么就是核心场景需要几个工具联动，但彼此不互通。

他们没有自己的 data footprint。数据躺在各个 SaaS 软件里，没有 ingestion，没有清洗，没有data governance。

所以真正创收，是把所有核心系统的数据通过 API 定期抽出来，normalize 之后落进 data lake，再建一套 catalog。

这个工作就好像水管工一点都不fancy，但它是后面所有 automation 的地基。地基打完，以前要掰扯半天的 churn、CAC、ad spend，直接让 Claude code /codex对着数据湖跑就完事了。

或许有人好奇，现在不是有 MCP 吗，直接让 agent 连数据库不就行了？

这个想法在实践中被证伪了：LLM 是 non-deterministic 的。同一个问题问十遍，可能给你十个答案。现在模型确实好了，十遍里能对八九遍，但八九遍对数据管道来说还是不可靠。

例如，你要从 CRM 里拉两万条 contact。Agent 走 MCP，得一条一条 list 再 get，每条烧几千 token，两万条跑下来 token 费吓人，中间还有不小的概率 hallucinate。而一段 Python 脚本调 API，跑一百遍结果一模一样，还能加 retry、定时调度、失败告警。

MCP 很适合 ad-hoc 查询，但替代不了真正稳定的 ETL。

最后，管道搭完，客户会不断想要新报表、新 dashboard，东西坏了也得有人修。所以计费天然是每月 retainer，比一单一单卖 agent demo 要更健康。

本期封面的艺术参考

本期封面参考法国艺术家费尔南·莱热（Fernand Léger，1881—1955）的机器时代视觉语言。

莱热早年在卡昂做建筑学徒，1900 年前往巴黎。第一次世界大战之后，城市、机器与物体成为他创作的中心；他以粗黑轮廓、圆筒、圆盘和相互咬合的几何形体，表现工业文明的新秩序。艺术家生平资料

大都会艺术博物馆将他约 1918—1923 年的阶段称为“机械时期”：画面不必描绘一台真实机器，而是用关节、活塞、杠杆般的抽象结构唤起机器时代。作品与风格资料

这与本文的判断恰好对应：企业 AI 的价值并不只来自显眼的 Agent，而来自 API、ETL、数据治理和监控这些相互咬合的基础设施。封面因此把 Agent 放在管道下游，让“水管工”成为真正维持系统运转的人。
