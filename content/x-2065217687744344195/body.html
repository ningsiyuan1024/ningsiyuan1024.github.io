关于Hermes Agent的个人笔记

Hermes的“自进化”短期靠 Memory 和 Skill 把经验外化；长期靠 Trajectory、GEPA、RL 把经验内化。

1. Memory：分层记忆

MEMORY.md / USER.md 记录环境和偏好；
Session Search 用 SQLite + FTS5 查历史会话；
Skills 记录可复用流程；
Honcho 做用户建模。

2. Skill

Hermes和 Claude Code/OpenClaw 的关键差别。

后两者的 Skill 更像静态插件。Hermes 的 Skill 可以由 Agent 自己创建、自己更新。连续 10 轮没沉淀 Skill，系统会提醒复盘；每次回复后，后台 Agent 也会检查有没有值得记住的事实和可复用流程。

3. Trajectory：把过程变成训练数据

Hermes 会保存完整执行轨迹：用户请求、模型回复、工具调用、工具结果和最终答案。

传统 Agent 跑完就结束。Hermes 跑完后，留下的是可检索、可评估、可训练的样本。

4. GEPA + RL：把经验内化
GEPA 用真实轨迹做文本级进化，不需要 GPU；RL 把大模型的 Agent 能力蒸馏到小模型里，目标是降本、提速、数据不出机器。

关于我自己的实践：

Memory 和 Skill 很有工程参考价值，RL 那层还偏研究向，链路搭起来不简单，reward 设计也容易出问题。
