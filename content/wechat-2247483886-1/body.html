导读

本文以内部视角系统地剖析了 AI coding 公司 Cursor 的组织与文化：旧金山线下高频协作、以人找岗的高门槛招聘、全员 dogfooding 与 fuzz 测试机制，以及“为最优秀开发者抬高天花板”的产品路线，为希望打造高密度人才型技术组织的读者提供可借鉴的范式。

“dogfooding” 的原意是 “eat your own dog food”——“吃自己家生产的狗粮”，实际意思是：用自己做的产品来做真正的工作，用实际使用来证明它真的好用、能用、值得卖。最早在软件行业里流行，用来反对那种“只给客户用、自己却不用”的做法。

近距离观察 Cursor 后发现，这家 AI 公司之所以跑得快，不是因为说了“AI 改变编程”，而是因为它在组织层面做了几件同时成立、但很少有公司能同时做到的事：第一，坚持 face-to-face 为中心，让决策、反馈、协作都在黑板旁和餐桌边完成，信息传递变成小时级；第二，招聘不是从岗位出发，而是从“出现了一个非常优秀的人”出发，全公司围绕此人设计角色并推动其加入；第三，全员真正使用自家产品，形成自下而上的 roadmap，再通过统一的 fuzz 测试把质量拉到能面向重度用户的水平；第四，在产品策略上拒绝“面向所有人”的容易路径，而是明确只愿被最强开发者往上拉，从而保持产品的专业度与技术含量。

通过这篇文章，可以清楚看到 Cursor 如何用文化、流程和人，支撑住一个高成长、技术导向、以使命为奖赏的公司形态，也能判断哪些做法可以迁移到自己的团队里，哪些必须建立在极高人才密度之上。

近距离观察：打入Cursor内部的60天

这是 Colossus “Company Dispatch” 系列的首篇，作者为 Colossus 的首席营销官，曾在 Stripe 和 Figma 的早期工作过。此系列的设定是：Colossus 或 Positive Sum 的成员，会以员工、投资人或非正式观察者的身份短期嵌入一家值得关注的公司，真实记录所见所感，再将这些观察整理成文。

作者最初通过一位前同事结识了 Cursor 团队。对方说这家公司希望认识一些在 marketing 上有独立视角的人。双方先进行了一次 30 分钟的交谈，随后她被邀请到 Cursor 位于旧金山的总部参观。又经过几次她认为是“非正式”的交流后，她写了一些自己的观察和想法发给团队，便回去继续原本的工作。

不久之后，她收到前同事的消息，才知道 Cursor 团队已经在背后讨论给她一个有报酬的角色，而她本人并未正式申请。这让她一方面感到意外甚至有些不适，另一方面也感到被重视。事实证明，这就是 Cursor 的行事节奏：推进迅速、边做边明确。两周之内，一台 Cursor 的笔记本电脑寄到了她在西雅图的住所，Slack 邀请也发了过来，她又安排了一次去总部的行程，开始正式与团队一起工作。角色的边界与期限被有意留得比较模糊，但核心任务可以概括为：利用她个人化的观察方式，帮助 Cursor 把自己的故事说清楚。

她之所以愿意接下这一项目，有两个直接原因。第一，去过办公室、与团队实际相处之后，她感到必须参与进来。她曾在 Stripe 和 Figma 的早期工作过，很清楚一种难得的“正在形成某件重要事情”的氛围是什么样的，她在 Cursor 又感受到了这种氛围。经历过这种氛围的人，往往会主动靠近它。第二，在 AI 时代，还没有一个真正意义上的“这一代的代表性公司”诞生，而 Cursor 看起来有机会做到这一点。她也很快发现，Cursor 的领导层的确有意愿重写一套新的公司构建范式，这对她而言极具吸引力。两个月下来，有些判断被验证了，也有不少地方与她的预期不同。以下是她目前所见的公司与文化样貌。

1. 旧金山办公室：为企业文化而设的空间

想真正理解 Cursor 的文化，必须去他们位于旧金山 North Beach 社区的办公室。那一带几乎没有其他初创公司，因此它的存在感并不像传统科技公司那样强烈。办公室给人的第一印象不像公司，更像大学里的公共活动室或食堂：如果事先不知道，很难判断这里是哪家企业。

办公室外没有 Cursor 的标志，墙上没有统一的企业海报，没有人穿公司周边，笔记本电脑上也很少看到 Cursor 的贴纸。取而代之的是，一群人安静地在自己的桌前工作，或者两三个人聚在一起讨论问题。这里使用的是黑板而不是白板，公司总裁 Oskar Schulz 甚至会很认真地分享他是从哪里找到最好用的粉笔的。家具是一位热爱欧洲复古风的退休技术人员从东湾淘来的杂糅款式。墙上摆着一排排书，既有教材，也有明显被翻阅过的工具书。

她早期拜访时，曾碰到一家日本银行的三位潜在客户来访。对方身着正装，由一位二十多岁的销售带着参观，销售还邀请他们从一大堆像积木一样码起来的能量棒、薯片和爆米花里取食。这一幕略显轻松甚至有些可爱，但整体氛围却很自然，没有刻意的包装。

Cursor 的文化高度偏向线下。约 86% 的员工在旧金山总部或新开的纽约办公室工作。如果需要同事的帮助，走过去直接交流往往比发 Slack 或开会更有效。很多协作都是临时围在一块黑板或某人的桌旁完成的。公司安排的固定会议并不多，他们非常重视保护深度工作时间，以便在一天内保持足够的灵活性。她询问是否有系统的文档时，有同事说：“Cursor 更像一种口述型文化。”

从 9 月初开始，她几乎每隔一周就会到办公室一次。她承认，只要在现场，工作流转就明显顺畅；回到家时，她常常会感叹“要是在办公室就好了”。

每天中午 1 点、一周六天，公司的厨师 Fausto 会准备午餐，大家围坐在公共餐桌旁用餐。Fausto 曾经一度想离开，因为团队规模增长过快，每天设计菜单的压力非常大。为了帮他适应节奏，团队为他做了一个 AI menu generator 供他参考。现在，他也在 Slack 里与大家交流菜品、听反馈、接受点菜。可以看出，这家公司希望每一个角色都具备主动性与创造性。

午餐与晚餐时间的谈话主题大多与工作相关，但“工作”被解释得更宽：有人会谈正在推进的 Cursor 项目，有人会分享正在思考的产品问题，还有人会讨论行业和产品的未来走向。她有不少时间就坐在餐桌旁听别人说，因为在这里坐三十分钟，就能听到一轮又一轮的思路碰撞。她在 2015—2017 年的 Stripe 也有类似体验，但 Cursor 的一个差异在于：餐桌旁经常会出现她不认识的人，因为大家习惯邀请聪明的朋友来办公室看看。她问联合创始人 Sualeh Asif，在公司建设上最担心的是什么，他说：“如果有一天大家吃饭开始聊天气，那就需要警惕了。”以目前的情况看，似乎还不必担心。

1. 招聘：以人设岗，而不是以岗招人

Cursor 的招聘方式非常特别。大多数公司是先发现业务短板，再开岗位、写 JD、搜简历、约面试、等待入职。而 Cursor 的逻辑是：如果发现了一个非常优秀的人，就应当先争取到他，再来想他在公司里最适合做什么。

具体来说，Cursor 的 Slack 里有一个 #hiring-ideas 频道。只要有人发现了值得关注的人，就会把名字贴进去。大家会迅速围绕这个人展开讨论、联络和面试，流程不会一成不变，但目标很明确：如果双方都有意愿，就尽快让他加入，最好下周一就能来上班。

团队的规模增长非常快。去年同期，公司人数还不到 20，如今已经接近 250。作者本人大概有四分之一的时间花在招聘上，这件事不仅被允许，而且被鼓励。#hiring-ideas 频道里不断有新名字出现。这里的“寻找人才”不是在 LinkedIn 上按照职位或公司搜索，而是从“这个人做过一件很像 Cursor 文化会做的事情”着手。

例如，他们注意到 Eric Zakariasson，是因为他在斯德哥尔摩组织了 Cursor 的 workshop。注意到 Ian Huang，是因为从用户使用数据里发现，有人经常在深夜用 Cursor 写代码。每当出现可能释放人才的市场事件，例如某家初创公司关闭、某家大公司裁员，Cursor 团队就会主动去其中寻找最优秀的那部分人。只要谁看到了一个出色的产品发布、一篇有分量的博客或一条有价值的推文，就会把创作者的名字贴在频道里，并附上一句：“我们要不要考虑他？”

如果大家意见一致，就会马上新建一个频道，专门讨论如何接近这个人。讨论的问题往往是：“他最喜欢做什么？”“他最擅长什么？”“我们能给他怎样的角色配置？”接着大家会匹配公司当前真正有挑战性、也足够有吸引力的问题，假设优秀人才会被难题吸引。有时还会请第三方了解该候选人的背景（这一点作者本人态度较为复杂，因为通常不会提前知会候选人）。

随后，会有一位 Cursor 成员作为与候选人的对接人，负责发起和推进所有接触，但候选人能同时感受到来自多位 Cursor 成员的关注。常见的一句话是：“你现在不考虑换工作没关系，我们可以先做一个小项目。”另外一个常用的方式是邀请对方来总部坐一坐，因为他们非常清楚，亲自到访办公室的体验往往能改变一个人的决定，同时也方便 Cursor 这边做进一步判断。她在办公室经常看到一些过往认识的优秀操盘手，有的人以“来看朋友”的名义出现，有的人离开后还特意嘱咐她“别说你看到我来过”。

尽管主动出击频率如此之高，Cursor 的录用率仍然非常严格。大多数公司都会说“人才最重要”，但真正做到“明明手头有很多事要做也宁可不将就”的公司并不多，Cursor 是其中之一。这样做的逻辑是：如果放宽标准，现在是省事，但后面要付出的管理和文化成本会更高。当前，创始团队仍然会亲自审批每一次录用，这一做法大概率会延续一段时间。

在促成候选人加入方面，Cursor 也很投入。曾在 Stripe 和 Notion 做首席设计师的 Ryo Lu 是一位 Apple 爱好者，于是 Cursor 就送了他一台早期的 Macintosh 电脑。Lukas Möller 给创始人写了一封冷邮件，表达了自己对编码的热爱以及对 Cursor 的欣赏，创始人甚至专程从加州飞到德国与他见面，他仍然没有答应。Oskar 说：“‘不’往往只是对话的开始。”一年后，他们再次飞到德国，这一次 Lukas 和他们一起回到了旧金山。Jordan MacDonald 原本对自己的工作很满意，在 Cursor 与她保持半年多的轻松接触、并且她身边的人陆续加入 Cursor 之后，她仍然没有动摇。某次聊天中团队得知她刚搬新家，作为收尾，他们联系了她的室内设计师，询问哪件家具可以起到关键作用，最终是一台咖啡机送到了她的住所，而她也在 10 月加入了 Cursor。

需要说明的是，Cursor 自己也意识到一个不足：在产品和工程领域，女性人才比例还不够高，这被列为优先解决的问题。

3. 人才密度：多重因素叠加后的组织形态

Cursor 能在如此早的阶段就吸引到大量优秀人才，是因为它同时具备了几项关键要素：有吸引力的使命、真正困难的技术问题、清晰可见的业务增长，以及极具执行力的招聘方式。

在产品与工程方面，他们正在做的是 UX 与机器学习交汇处最有挑战的部分，最近发布的 Cursor 2.0 便是例证：既有自研模型，也有专为 agent 工作流设计的新界面。在市场拓展方面，Cursor 几乎以“没有销售团队”这一设定达到了 1 亿美元 ARR 的规模，如今成立了销售团队，要在 2025 年结束前将该数字再提升一个数量级。Slack 上的 #closed-won 频道几乎一直在更新成交信息。

整个公司有 50 多位曾经的创始人，占全员的五分之一以上；接近 40% 的员工来自 MIT、Harvard、Columbia、Cornell、CMU、Stanford、Berkeley、Yale 这些学校，但很少有人在日常交流中提起学历。有的人将 Cursor 作为第一份工作，有的人则来自 Figma、Stripe、Segment、Plaid、Notion、Vercel、Dropbox、GitHub、Uber 等公司，确实是一个多元背景的聚合。

这种高人才密度在日常工作中的表现非常直接：几乎看不到明显的“无能”。大家做事的姿态是自然、自信的，而不是为了展示而展示。她曾注意到，办公室二楼要通过一段坡度较大的无扶手楼梯，她问为什么不装扶手，对方的回答是：“大家都能走上去。”

联合创始人 Michael 多次说，他希望 Cursor 成为一个“适合高度自驱的 IC 的地方”。从现在的情况看，这个目标正在实现。在这里，人们更多依靠自己的热情和意志力推动项目，而不是等待管理者分配任务。IC 在这里是很受尊重的角色。联合创始人 Aman Sanger 仍然是一位亲自写代码的 IC，作者对他的典型印象就是：坐在办公室一角，一天大部分时间都在专注编码，几乎不被打扰。公司内部有一条清晰的工作方式：谁对某件事有兴趣，或者谁对某件事有迫切感，就直接去做；同时，公司也敢把一个有难度、有影响力的项目交给某个人，哪怕他的职级或所在团队与项目传统归属不完全一致，只要他能负责到底即可。

销售团队的一位新成员感慨说：“我上一家公司需要 30 天之后才能允许新员工跟客户通话，在这里不到 30 小时我就开始和客户交流了。”工程团队也有类似的情况。有一次大家对“Cursor 在浏览器中能做到什么”产生兴趣，一小组人主动提出周末一起解决这个问题，参与者包括资深工程师、前创始人以及在 10 天内完成 Cursor CLI 的工程师。他们放下手头工作，全程在线下合作，直到做出成果。参与者说，这是他职业生涯里最愉快的一次工作经历。类似的事情在 Cursor 频繁发生。

之所以能如此高效，一方面是因为人才密度本身很高，另一方面是因为“重要问题的数量”与“可投入的人数”之间的比例很高，几乎不存在无事可做的状态。她回想起早些年在 Stripe，有一次洗手间里出现了一块不必要的企业标识，联合创始人 Patrick Collison 很快就去确认学习与发展团队是否出现了臃肿。在 Cursor，她没有看到类似的浪费。

4. “有阅历感的年轻人”

在很多组织里，“年轻”常常意味着“专业性还不够”或者“做事能力不错但表达上过于随意”。作者原本以为在 Cursor 至少会看到后者，但实际情况是：尽管团队平均年龄不高，整体却显得温和、得体、沟通清晰，且在细节上有礼貌。

令她印象更深的是，很多年轻同事表达观点时，会引用硅谷发展史、世界历史、经典文化、艺术、其他行业的成熟做法，或者是他们长期关注的优秀从业者的实践。这说明，他们并不是只靠个人经验做判断，而是在持续吸收外部世界的信息，因此更容易对不同类型的问题提出结构化的处理方式。为了分享这些思考，很多人会在 Slack 开设自己的“brain”频道，定期发布个人的观察和观点，不一定期待反馈，但好的内容自然会获得关注。受欢迎的内容往往不是为了“证明自己做了很多事”，而是关于产品形态、客户洞察、架构选择等更本质的问题。

她特别注意到，团队内部的沟通几乎没有过度的网络化口吻，也没有大量的表情包泛滥。她看到的非工作类信息包括：有人组织去旧金山交响乐团听 Vivaldi《四季》，有人分享纽约和旧金山晚上 9 点跑步的合影，有人转发并温和调侃一篇写得不够准确的 AI 报道，还有一个名为 #laundry 的频道，每周会有机器人发起“洗衣站会”，大家认真讨论如何折叠床单，还发起投票看哪款 humanoid robot 会最先帮我们铺床。团队整体的行为风格是克制而稳定的，Slack 里最常用的表情是 ♥️。当出现问题时，大家的反应也比较成熟：先确认准备工作做得不错，再讨论如何改进，而不是追责。

外界有人把 Cursor 形容成996，事实上公司没有这样的硬性要求。之所以会给人这种印象，是因为很多人确实热爱手上的工作，并愿意投入更多时间。节奏是自驱的，不是被要求的。刚加入时，作者也有过短暂的“节奏过快”的感受：待办事项很多，也不确定自己做的是否是最重要的事。但当她意识到，这其实是公司对她能力的信任，是高标准招聘的延伸，同时她也逐渐理解了公司内部如何运作之后，这种紧张感就转化成了成就感。她也强调，工作节奏和工作态度在组织里是高度传染的：如果同事反应快，你也会；如果同事周六进办公室，你也会。Cursor 的默认节奏就是快，而团队整体对这种节奏是接受的。

5. Dogfooding：从内部把产品“养大”

Cursor 一份早期的文化说明里写过一句话，大意是：全世界大概没有哪家公司能做到像 Cursor 这样，让每位员工每周都在使用公司的主产品；能与之相比的大概只有 Apple 员工用 Mac 和 iPhone。也就是说，Cursor 的员工几乎一直在使用 Cursor。

因此，产品的很多方向是自下而上长出来的。只要有人觉得某个功能应该存在，这个理由就足够启动研发。与此同时，Cursor 的用户群体也会在 X、Reddit、LinkedIn、Hacker News 上频繁给出改进建议，还会直接发消息给员工。团队成员甚至打趣说，有时候外出社交都会被产品反馈打断。

一旦有人形成了明确的产品想法，他可能会在每周的产品演示会上展示，也可能直接开始动手做。偶尔会出现两个人同时做了类似的方向，最后上线的版本通常会合并两边最好的设计。

新功能完成后，会先推到公司内部使用，观察大家是否真的会用，同时收集改进意见——也可能观察到它自然被淘汰。因为 Cursor 员工本身就是目标用户，所以大家会先在内部寻找产品市场契合度。Tab、CmdK、Agent、Bugbot、background agent 这些后续广受欢迎的功能，都是通过这种方式诞生的。

她非常喜欢的一个频道是 #braintrust，所有人都会在这里请求对自己正在做的功能进行快速反馈，很多时候是通过简单的表情投票来判断。例如曾经有人提出要不要删除某个键盘命令，就让大家用不同的表情表示“可以删除”或“我在用，请保留”。这种方式既高效，又能迅速聚焦真实用户的声音，也能引出更高质量的讨论。公司在对外表态时也非常明确：其他公司可以去做“降低使用门槛”，“让更多人能用”；Cursor 更希望做的是“提高上限”，让本来就很强的开发者也能觉得这是明显更好的工具。

高频的内部使用还有一个直接结果：Cursor 非常善于调整默认设置、减少不必要的选项、删除低使用率的功能。Slack 里经常能看到类似的问题：“这个设置还需要吗？”“能不能减少一次点击？”“有多少人在用？”“能不能删掉？”。

这在多数公司是很难做到的，因为要牵涉到历史包袱、跨团队协调和用户预期。但 Cursor 因为始终把内部版本跑在前面三个月，所以可以更快试错，把成熟之后的版本再推给外部用户。

需要指出的是，这并不仅限于产品和工程团队。Cursor 的 go-to-market 团队技术能力也很强，他们用 Cursor 搭建内部工具、更新官网、做 dashboard。#built-with-Cursor 频道里可以看到很多这种成果：乒乓球场地预约管理、团队成员的婚礼网站、Cursor 快捷键的可视化页面、给办公室犬投喂的小程序、以及一个基于大都会艺术博物馆藏品做的地理猜测小游戏 Metguessr。这些都不是公司强制要求的，而是大家愿意用产品来解决身边的问题。

6. Fuzz：上线前的集中性破坏测试

“Fuzz” 是 Cursor 很有特点的一项仪式。每当有一个重要的版本即将发布，比如新的客户端版本或官网的较大更新，产品负责人就会在公共频道里发出通知，大家集中到某个空间里，对这个版本进行集中测试，目的就是“把它挑出问题来”。

有时候产品负责人会准备一些简单的食物以提高参与度，但其实大多数人本身就有很强的责任感，愿意投入时间去避免带有明显问题的版本上线。Cursor 的早期文档里写得很直接：错误在所难免，但只要是发布给用户的，就应当尽力避免出现让用户失望的 bug。尤其是当公司要求用户每天大量在 Cursor 中写代码时，性能问题或功能缺陷都会成为用户流失的诱因。

测试开始后，产品负责人会发出最新构建的链接和说明，大家就开始安静地在各自的电脑上寻找问题。整个过程通常持续一小时左右，期间只有键盘敲击声，大家会把发现的 bug、界面细节问题、未覆盖的边界条件、不够顺畅的交互等，全部整理到 Slack 中。有时还会就最合适的实现方式进行快速讨论，甚至用投票来决定。到结束时，通常会形成一张较长的待办清单，需要在正式上线前完成。产品团队会对全员参与表示感谢，然后准备夜间加班修复，很多时候指出问题的人也会加入修复。

这种做法看似简单，但它能确保一个事实：最终发布给用户的版本，是在真实的、重度的、了解产品背景的使用情境下跑过一遍的。

7. 建设性的“摩擦”

在 Cursor，大家会比较频繁地互相指出对方工作中可以改进的地方。这对不习惯这种文化的人来说，一开始会略显直接。但这背后有一个前提：这里聚集了很多真正懂得好产品是什么样的人，他们对“还差一点点才到位”的部分非常敏感，也愿意说出来，并且通常也愿意一起把它补上。

作者在 Stripe 时的同事 Eeke 曾用“micro-pessimist, macro-optimist”来形容这种工作方式：在细节上保持挑剔，但在整体上保持乐观，相信团队正在做有价值的事。Cursor 的状态非常类似。大家在执行层面会提要求，会问“能不能再好一点”；但大家同时也相信这家公司正在朝一个正确、而且足够大的方向走。

这种文化与创始人的行为方式密切相关。Michael 在公司问答环节中会主动鼓励大家提“尖锐的问题”；Sualeh 则会私下询问大家“你现在最担心的是什么”。这种公开和私下的双向反馈机制，使得“提出问题”这件事不会被视为冒犯，而是被看作推动产品和公司前进的一部分。

当然，这种文化如果与自负、内部政治、表达不清或情绪化绑定在一起，会变得有害。但 Cursor 的可贵之处在于：这里提出问题的人，往往也是愿意解决问题的人，因此“摩擦”能最终转化成产品质量和组织能力的提升。

8. “抬高天花板”作为产品与组织的价值取向

Cursor 在产品定位上有一个非常明确、也相对罕见的选择：它的核心目标用户是最好的专业软件开发者。这个选择略带争议，因为现实中有很多并非开发者的人也在使用 Cursor，并且反馈良好。但 Cursor 并不因此改变核心取向。它的态度是：市场上可以有很多面向“降低门槛”的产品，但 Cursor 更愿意被最具能力的用户向上拉，从而推动整个软件构建方式的升级。

产品设计里有一句话是：“你要谨慎选择你的用户，因为他们会把你的产品往他们所在的位置拖去。”Cursor 就是有意识地选择被顶级开发者拖向更高的专业度和复杂度。作者对这种选择表示尊重，因为这条路径往往意味着市场传播上不会那么“温暖和广泛”，但能保持产品的锋利度和技术含量。

这一价值取向也反映在招聘与面试上。Cursor 的工程面试以难著称。作者问过团队为什么要设置这么高的难度，团队的回答是：如果题目太简单，候选人无法展示真实水平；而他们宁可出现“错过一个好人”的情况，也不愿意出现“招聘进了不适合的人”的情况。这样的标准，实际上就是在“为天花板设计”，而不是“为地板设计”。

作者在 Cursor 工作期间，也逐渐习惯用“如果我们要做这个问题的高天花板版本，会是什么样”的方式来思考，这个思路会自然把人的目标拉高。

9. 使命本身就是回报

一家公司如果拥有高密度的人才、快速的增长、良好的产品势能，会不可避免地出现一个问题：大家究竟是在为什么而投入这么多时间和精力？在 Cursor，这个问题的答案比较清晰：使命本身就是最重要的回报。

Cursor 对外讲的故事通常是“提高开发者生产力”。这是一个成熟而易于理解的商业叙事。但公司内部真正被反复谈到的，是“代码”以及“让代码生成成为世界底层结构的一部分”。作者在加入 Cursor 之前，并没有如此具象地意识到，我们很多社会运行和创新活动，实际上是被“我们能不能高质量地写出软件”这个能力所限制的。交通信号控制系统、科研分析工具、音视频制作软件、医疗记录系统、供应链管理系统、航空调度系统……这些都依赖于软件。如果“写软件”这件事能被做得更自然、更精细、更高效，就会直接影响到现实世界的进步速度。

她曾与一位同事散步，问他如何理解 Cursor 的使命。他谈的是：要构建真正有用、可靠、且有美感的软件；要有一套工具能在每一层抽象上给到开发者精细的控制；要在同一个对人类自然的界面里把人与 AI 之间的语言鸿沟弥合掉；要让构建软件这件事更接近艺术创作。这些话如果单独拿出来看，可能会显得理想化，但当她在 Cursor 实际工作了一段时间之后，再听到这些表达，就能感受到这是团队日常思考的一部分。

从这个角度看，Cursor 更像是在做一项“登月式”的任务。真正的风险反而是：如果商业上的成功来得太早、太顺利，它反而可能分散公司的注意力，让公司不再持续选择最难、但最有价值的路径。Michael 会在全员会上提醒大家：“增长有时候会遮蔽执行上的问题。”这与 Stripe 曾经反复强调的“We haven’t won yet.” 有异曲同工之处。但从她的观察看，Cursor 的成员并没有沉浸在估值、营收、用户数的表层兴奋中，他们更兴奋的是某个产品能力做通了、性能更稳定了、交互更顺了。

她最后举了一个很有说服力的细节：在 Cursor 工作的这段时间，她几乎没有听到员工讨论“发财之后要做什么”。在很多快速成长的公司早期，比如 Stripe、Figma，当公司估值快速拉升时，大家在餐桌边常常会谈股票、谈未来的财务安排。但在 Cursor，随着公司估值上升，她没有听到类似的讨论。她的解释是：多数人即便明天可以退休，他们仍然会做现在在 Cursor 做的事，而这恰恰说明，使命本身已经足够构成回报。
