一、贯穿主线的三个问题

最近 AI4AI 很火，很多业内人士离职创业，进入这个领域。但大家使用的概念很多：AI4AI、进化、自进化、元进化，以及 Recursive Self-Improvement，也就是递归自我改进（RSI）。这些概念之间究竟有什么区别和联系？

本文主要关注三个问题。

第一，最近这些 AI4AI 工作的共性是什么？

第二，进化、自进化、元进化和 RSI 分别是什么，它们之间有什么关系？

第三，怎样把这些概念落到一个真正可执行的工程系统里？

先从 AI4AI 的定义出发，讨论在以 Agent 为主经验时代，怎样把改进做成经验闭环；接着讨论经验如何规模化，怎样把高价值问题转化为可验证的任务；最后介绍工作案例Frontis-MA1。

二、AI 自我改进：从历史设想到工程闭环

人类讨论机器的自我改进，其实开始得非常早。1863 年就有作家提出：如果机器能够演化，或者能够自我进化，那么人类可能正在创造自己的继承者。后来，图灵以及数学家 I. J. Good 等人也讨论过类似问题：如果机器可以参与下一代机器的设计，而改进过程本身又能获得反馈，就可能出现指数级的智能增长。

2003 年提出的 Gödel Machine，则试图从形式化角度讨论这个问题。用非常简化的话说：如果一个机器能够证明某项自我修改是有益的，它就可以执行这项修改。

大家很早就在追问：智能是否拥有自我学习、自我改进的能力？今天这个概念再次受到重视，是因为 AI 已经开始真正进入 AI 研发流程。国内外的模型公司都在使用自己的模型或 Agent，帮助设计和训练下一代模型。过去的思想实验，正在逐渐变成产品和研发闭环。

看几个例子。

Google DeepMind 的 AlphaEvolve，把算法和训练基础设施变成可评估的进化对象。大语言模型生成代码修改，系统执行修改并进行评测，保留更好的结果，再继续迭代。它曾被用于数据中心调度、Kernel 优化和大模型训练效率优化。

另一个例子是围绕 nanoGPT 的自动研究实验。研究者把训练过程压缩为一份可以直接修改和执行的训练代码，给 Agent 固定的运行时间和统一的评测标准，让它持续提出修改。运行一段时间之后，Agent 就能独立完成多轮模型训练实验。

Darwin Gödel Machine 一类工作修改的未必是基座模型参数，而可能是 Agent 的 Harness——包括工具、工作流及外围机制。系统利用软件工程或编程任务上的可验证评测，搜索出更好的 Agent 结构。

还有一些工作在自动化机器学习任务内部搜索更好的算法，同时在外层重新改写 Harness 或 Agent。经过多轮迭代后，新 Agent 不仅在进化时见过的任务上表现更好，在域外任务上也可能取得提升，甚至降低 reward hacking。

这些工作的共同结构非常明确：AI 参与 AI 研发的某个环节，提出修改；外部环境执行修改；评测器或另一个模型评价结果；系统进行筛选、回滚并继续循环。由此形成一个 AI4AI 的演化闭环。

三、AI4AI、进化与自进化的区别

我认为，AI4AI 的最小共识是：AI 参与构建或改进 AI 系统。

人类负责定义边界，AI 在边界内执行提出修改—实现—执行—评价—筛选—继续迭代的循环。因此，AI4AI 和进化不是同一个层面的概念。

AI4AI 描述的是一种任务关系，即谁在改进谁。只要 AI 参与了另一个 AI 系统的构建或改进，无论作用对象是模型、算法、训练代码、Harness 还是硬件，都属于 AI4AI。被改进的系统可以是外部系统，也可以是 AI 自己。

进化（evolution）描述的则是改进机制：系统在某个任务上不断提出候选方案，真实执行并获得反馈，再保留更好的结果。

如果前后的两个 AI 指的是同一个系统，就涉及自我改进。但普通进化与自进化之间还有一个关键差别：经验有没有留下。

假设一个系统在某个任务上不断搜索，最后得到更好的 solution；但系统一旦重启或换到另一个任务，又从最初的方案重新开始。那么它虽然完成了进化，却没有形成跨任务或跨轮次的积累。

如果搜索或进化结束后，系统能把与任务和改进有关的经验保存下来，并让这些经验影响未来的系统，我们就可以称之为自进化（self-evolution）。

换句话说，进化产生的可能只是一个更好的解决方案；自进化不仅产生解决方案，还留下可复用经验。下一轮运行时，系统不再从同一个起点出发，而是因为过去的经验获得了更好的初始状态。

这也是为什么今天的 Agent 可以越用越好。Agent 与用户、任务和环境交互时会产生大量经验，这些经验主要有三个落点。

第一类是内容资产，例如 Skill、Memory、知识条目和可复用代码。早期的典型例子，是 Agent 在 Minecraft 环境中不断交互，把成功经验积累为之后可以调用的技能。

第二类是机制资产。系统从成功与失败中总结依据，继而改变自己的策略、流程、工具选择或执行结构。被更新的不是一段具体知识，而是系统处理问题的方式。

第三类是参数资产。当 Agent 能稳定产生高质量经验后，可以把这些轨迹用于训练或微调模型，把经验内化到模型参数中。SkillRL 一类工作会把模型与环境交互的轨迹整理成 Memory 和 Skill，再把 Skill 与基础模型结合训练，让模型更会使用这些经验，并获得更快的收敛。

不论经验最终写入 Harness 还是模型参数，只要它能够改变系统未来的行为，系统就从一次性的进化走向了自进化。

四、元进化：让系统学习如何改进

自进化并不是终点。下一步是元进化（meta-evolution）。

我们把直接接触任务与环境、负责解决问题的 Agent 称为 Task Agent。Task Agent 在自我改进循环中会留下完整轨迹：改进前的方案是什么，改进后的方案是什么，中间修改了什么，执行结果怎样，为什么变好或变差。

这条轨迹不仅包含怎样解决任务的经验，也包含怎样完成改进的经验。如果另一个模块能够学习这些改进经验，它学到的就不再是某个任务的答案，而是如何进行更有效的进化。类比元学习是学习如何学习，元进化就是学习如何进化。

承担这一功能的改进器可以内置在 Task Agent 中，也可以是外部的 Meta Layer。两种结构实现的是相似能力，只是放置位置不同。

部署后的 Agent 进化，大致可以分成三个层次。

第一个层次，Task Agent 进行自进化，判断哪些内容、机制或轨迹应该积累为经验。

第二个层次，Task Agent 内部拥有一套可以继续变化的改进机制。它不仅积累经验，还能学习怎样积累、筛选和利用经验。

第三个层次，在 Task Agent 外部设置功能独立的 Meta Layer，由它负责改进 Agent 的改进策略。进一步地，Meta Layer 自身也可以成为改进对象，这就出现了递归嵌套：系统不仅修改 Task Agent，也修改“修改 Task Agent 的方法”。

为什么需要元进化？假设我们给两个系统相同的五小时预算，让它们产生自己的后继系统。如果下一代系统能够比上一代更快、更可靠地产生更强后继，那么改进过程就开始形成飞轮：不仅越改越好，而且越改越快。

五、从元进化走向 RSI

RSI 目前在学界没有完全统一的定义。我的理解是，它必须比一次性的元进化更强：升级后的改进器要能够接管下一轮 AI 进化，并持续产生更强的后继系统，从而形成复利式、甚至指数式的智能增长。

有机构把相关能力划分为 L0 到 L3。L0 阶段，AI 可以改进某项任务，但速度可能慢于人类；L1、L2 阶段，AI 的改进能力逐渐接近或超过人类；到了 L3，系统投入一份智能或算力，能够产生大于这份投入的后继智能。这样，系统才可能“左脚踩右脚”，形成持续复利。

这里必须强调：我们后面介绍的工作，是迈向 RSI 的一步，并不是已经实现了 RSI。

为了研究元进化，我们需要的不只是某个任务最后得了多少分，而是一条完整的改进轨迹：AI 系统的起始状态是什么，做了什么修改，修改后执行出什么结果，为什么得到这个结果，以及其中是否存在可复用的改进经验。

六、为什么选择机器学习工程作为实验场

我们选择机器学习工程（Machine Learning Engineering，MLE）作为实验场，是因为它满足几个关键条件。

第一，候选 AI 算法通常以代码形式存在，可以真实执行。

第二，任务结果可以量化评价。

第三，执行日志和代码修改可以追溯。

因此，我们不仅能得到最终分数，还能提炼“怎样改进 AI 算法”的经验。如果想规模化获取这类经验，任务必须同时具备高价值、可执行和可评价等性质。

MLE-Bench 是一个典型例子。它来自 Kaggle 等机器学习竞赛任务。Agent 会获得比赛描述、数据和人类表现等信息，然后自行训练、测试模型，解决任务并生成可量化的结果，最后与人类排行榜进行比较。完整过程天然构成一个可以收集改进经验的闭环。

我们沿着两条路线扩展任务。

第一条路线是 NatureBench，也就是从前沿科研论文中构造 NatureGym。我们从 Nature 系列子刊中提取任务，隐藏论文中的原始解决方法，并禁止 Agent 联网搜索答案，由此检验 AI 面对未知问题时能否复现甚至超过人类科学家的结果。

我们先从十余本 Nature 系列子刊中提取了五千多个候选任务，再经过 Agent 测试和大量人工筛选，得到 90 个忠于原文、可以真实评价的高质量任务，覆盖细胞组学、蛋白质等六个科学领域。它们既是高价值科研问题，又能被 AI 方法解决和量化评估。

第二条路线是扩大 OpenMLE-Gym 中的机器学习任务规模。我们从公开数据集、竞赛和高质量锚点任务中筛选并统一格式，形成跨模态、跨任务的训练环境。对模型来说，每个任务都包含明确的数据、训练集、测试集和评测器；对研究者来说，每一轮代码修改和执行反馈都可以被记录为进化轨迹。

过往的 MLE Agent 工作大致沿三条路线展开：

一是让经验可获得，例如构造任务、沙箱和可验证执行环境；

二是让经验可使用，例如在推理阶段利用搜索和 Memory 组织历史改进经验；

三是让经验可内化，即把生成、改进和调试机器学习算法的能力训练进模型参数，使其成为跨任务能力。

Frontis-MA1 和 OpenMLE 尝试把这三条路线连接起来。

七、OpenMLE：把任务、训练和搜索接成一个系统

OpenMLE 是一套面向 MLE 元进化研究的全栈开源系统，主要包含三个部分。

OpenMLE-Gym 提供统一的任务形式、数据、任务包、隔离执行环境和评测器，让每一次改进都能获得真实执行反馈。

OpenMLE-ERL 负责训练模型。我们通过 SFT 和在线 RL，把构造、改进和调试机器学习算法的经验内化到参数中。

OpenMLE-Evo 负责 test-time scaling。它利用长期搜索和快速记忆，在推理阶段组织并复用进化经验。

在这个系统上，我们训练了专门用于构造和改进机器学习算法的 35B 模型 Frontis-MA1。

整个系统围绕四种原子程序进化操作展开：Draft、Improve、Debug 和 Crossover。这四种操作本身并不全是新的，关键在于训练与搜索使用相同的动作空间。

这样做有两个好处。第一，每次训练只需要看从一个算法节点到另一个算法节点的局部变化，不必把完整的长轨迹全部放入上下文，因此上下文更短。第二，模型训练时学到的操作与搜索时真正调用的操作保持一致，搜索产生的新轨迹又能反过来训练模型。由此，参数学习和进化搜索形成了闭环。

八、怎样训练一个改进器

SFT 阶段，我们不仅收集高质量的最终解决方案，也收集进化式搜索中的局部改进轨迹。

例如，一个父节点的程序是错误的，子节点完成了 Debug，不仅修复错误，而且取得更好的结果。这样的“错误方案—修改动作—正确方案—执行反馈”比单独的正确答案包含更多改进信息。我们最终获得了约 2.6 万条 SFT 数据用于训练。

RL 阶段，Policy Model 同样在搜索树上进行采样。每一步操作都会从一个节点生成新的 AI 算法；算法在真实环境中执行并获得评分；一组候选结果再通过 GRPO 等方法反馈给 Policy Model。

不同机器学习任务的指标差别很大：有的指标越高越好，有的越低越好，数量级也不相同。因此，我们首先把各任务结果归一化到统一奖励范围。如果任务带有人类排行榜，可以把人类最高分和最低分作为参考边界；没有排行榜时，则结合理论边界和实际采样结果动态估计。

此外，我们会把组内中下游候选的奖励截断为零，因为目标不是让模型产生“还可以”的方案，而是让改进器提出真正优于过往方案的新算法。为此，我们还使用类似 entropic advantage 的指数奖励设计，显著抬高每组 best candidate 的优势，鼓励模型寻找具有突破性的候选方案。

九、OpenMLE-Evo：让搜索真正积累经验

训练好模型之后，还要把它放入长程进化搜索。我们参考了 AIRA、AlphaEvolve 等工作，但更加强调进化经验的积累。

搜索树中的每一个节点都有一张经验卡，记录节点得分、相对父节点的提升、方法摘要、新颖性及其他元信息。

经验卡有两个用途。

第一，决定节点的采样概率。系统会综合节点自身得分、相对提升和 novelty，选择更值得继续探索的节点。

第二，为新节点提供经验。选定某个节点后，系统不会简单地重新生成，而是检索并总结其兄弟节点和祖先节点的经验，提取它们采用的方法、遇到的问题和失败原因，再把这些信息注入基座模型，生成下一代候选方案。

与参考搜索方法相比，这种机制在单次调用中使用的 token 更少，在相同 token 预算下得到的效果更好，也就是说进化效率提高了。

在 MLE-Bench Lite 上，Frontis-MA1 配合 OpenMLE-Evo 显著提高了模型表现；加入异步搜索和经验先验后的 OpenMLE-Evo-Max 还能进一步提升 Medal Average。论文报告的对应结果为：基础模型 39.39%，OpenMLE-Evo 60.61%，OpenMLE-Evo-Max 71.21%。在固定计算预算下，35B 模型与搜索策略的组合达到了更大模型才能达到的水平。

消融实验还显示，训练得到的改进器和进化搜索算法都各自带来收益；这套搜索策略也能帮助其他模型提升。在留出的 NatureBench Lite 上，模型和搜索方法都表现出一定迁移能力，说明学到的改进经验并不只对训练时见过的 MLE 任务有效，也能扩展到部分科学问题。

十、通往 RSI 的可执行路径

让可执行证据持续形成可使用的经验，把经验用于下一轮改进，再进一步优化改进器本身。

未来想走向指数式进化的 RSI，还需要解决几个问题。

首先，要扩大高价值任务的范围。人类社会中大量重要问题目前不可执行或不可评价，需要逐步把它们转化为可以执行、验证和反馈的任务。

其次，要贯通 Agent 与世界交互时产生的轨迹，把快速记忆、Skill、Harness 和参数训练连接起来，打通经验的不同落点。

最后，评价目标不应只是模型在某个 benchmark 上刷到多高的分数，还要判断：在相同预算下，新一代系统的改进能力是否真的比上一代更强，它产生后继系统的速度和质量是否持续提升。

下一步真正需要证明的是：改进后的 AI 系统能否接管自己的后续改进，并持续产生更强后继。如果能稳定做到这一点，我们才可以说正在稳步接近 RSI。

Q&A

1. 元进化是否等同于 Coding Agent？

问： 元进化是否也等同于 Coding Agent？

答： 至少在当前阶段，Coding Agent 是实现元进化的一条非常现实的路径。因为 AI 系统主要由代码构成，如果系统要修改自己，或者修改自己积累和使用经验的方式，就需要很强的编码能力。

但二者不完全等同。已经有团队尝试把硬件优化做成可进化闭环。未来的元进化可能超越 Coding Agent，与硬件和物理世界形成循环交互。

2. Meta Layer 是否相当于给模型外挂元进化能力？

问： 与 Task Agent 自己的元进化相比，Meta Layer 是否相当于把元进化能力外挂给其他模型？

答： 两种结构承担的是类似能力。

一种做法，是把元进化能力放进 Task Agent 内部，让 Agent 自己具备修改改进机制的能力。另一种做法，是让 Task Agent 专心完成任务，不要求它直接自指；在外部增加一层机制或另一个 Agent，专门负责改进 Task Agent。后者就是 Meta Layer。

3. 经验库不断增长，怎样处理检索错误和知识冲突？

问： 自进化或元进化积累的知识库不断增长后，检索错误和知识冲突可能抵消学习收益。怎样设计经验淘汰和更新机制？

答： 这正是为什么我们需要元进化。如果只做任务层面的自进化，经验一定会爆炸式增长。

现在常见的办法，是由人设计策略去整理或淘汰 Skill、Memory，甚至淘汰某些机制。但更进一步，系统需要学会怎样设计经验沉淀机制：由 AI 判断什么经验对自己真正有用、什么应该合并、什么应该淘汰，而不是永远由人手工规定。

4. 学术界算力有限，怎样研究 scaling 和元进化？

问： 学术界算力资源有限，怎样验证 scaling 效果？

答： 算力有限不代表没有问题可做。大厂可能直接进化自己的大模型或复杂 AI 架构，学术界可以选择高价值、可检验的 AI 或科学任务，在这些任务上验证进化、自进化和元进化机制。

进化研究也不一定必须使用大模型。我们曾在 MLE 上训练和测试 4B 模型，同样看到很明显的提升。学术界可以研究的一个重要问题，就是怎样让不同资源条件下的系统都获得较好的元进化效果。

5. 经验双落点具体指什么？

问： 经验双落点是什么？

答： 当前 Agent 大体由参数化模型和 Harness 两部分组成。因此经验也有两个主要落点：一个是写入外部的 Memory、Skill 或 Harness；另一个是通过训练写入模型参数。

6. 只做搜索树，不进行在线 RL，算元进化吗？

问： 如果不通过在线强化学习把知识内化，只使用搜索树，可以算元进化吗？

答： 单纯搜索是一种改进，也就是进化，但它未必形成可复用经验。

如果搜索树维护 Memory，它可以成为自进化系统。再进一步，如果系统记录相邻节点之间的变化——父节点是什么、子节点是什么、边上发生了什么修改、结果改善了多少——并把这些信息积累下来，用于学习如何改进，那么它可以具有元进化意义。关键不在于一定使用哪种训练算法，而在于改进经验能否被保存、学习并用于未来改进。

7. 垂直科研模型与专用 Harness 能否形成 RSI 路径？

问： 面向具体科学问题，科研 Harness 能否和垂直模型的权重一起做 RSI？

答： 可以。垂直模型配合专用 Harness、工具和接口，能够在具体科学任务中收集大量经验。这些经验可以再次训练垂直模型；更强的模型又能产生更多、更高质量的经验。只要闭环真正转起来，就可能形成自进化或元进化。

8. MLE 具体使用什么模型？

问： MLE 用的是哪一种模型？

答： MLE 不是一个单一模型任务。它包含表格、图像、时序等多种输入模态；即使同为图像任务，也会有分类和分割等不同问题。Agent 会根据具体任务生成相应代码并选择相应模型。详细案例可以参考技术报告，里面展示了方案怎样随着进化轮次获得更好的结果。

9. 元进化与递归自我改进有什么区别？

问： 元进化和递归自我改进有什么区别？

答： 最终目标是 RSI。RSI 的理想状态是系统不仅越改越好，而且改进速度也越来越快，超过人类并实现自我加速。

我认为，元进化是实现 RSI 的必要能力或必要性质。无论这种能力是人为设计的，还是系统自己形成的，AI 的“改进能力”本身都必须持续增强。但具有元进化能力，并不等于已经实现 RSI。

10. 怎样向搜索节点注入相关经验？

问： 选择一个节点继续改进时，怎样进行 Memory Injection？

答： 我们为节点维护经验卡。系统不会把所有兄弟节点和祖先节点都塞进上下文，而是加权采样几个对当前节点最重要的方法，然后由模型总结相应经验卡：这些节点使用了什么方法，遇到什么问题，哪些修改有效。总结结果再注入基座模型，用于生成新的候选节点。

11. 怎样评价 AI 是否真的越改越好？

问： AI 越改越好，是通过测评数据集判断吗？

答： 需要在整个进化过程中反复评价系统，观察相邻版本之间的增量。除了判断第一个版本是否优于第零个版本，还要比较第二个版本相对于第一个版本的增长，是在加速还是在收敛。

这也涉及持续学习。Continual Learning 一类基准会考察 Agent 在序列任务中能否积累和总结经验。如果它真正形成经验，后续表现应该逐渐提升。

元进化本质上也具有元学习性质。只要研究涉及跨任务、跨领域和多任务，就需要足够多样的任务，才能迫使系统学习可迁移的改进能力，而不是记住单一任务的技巧。

12. 怎样防止系统学会利用评价指标？

问： 如何保证元进化进行到后面，不会直接学会利用评价指标，产生 reward hacking？

江澈： 单一任务的单一指标比较容易被利用；但如果任务足够真实，需要运行多轮，并由大量不同任务的结果汇聚成评价，指标就更难被 hack。

进化评价应该建立在真实任务指标的变化之上。随着任务规模、多样性和复杂度增加，系统利用某个局部漏洞获得高分的难度也会上升。有相关工作观察到，仅通过增加任务量和迭代轮数，reward hacking 就有所下降。

13. Agent 发展到后期，更需要算法优化还是工程优化？

问： Agent 越来越难优化，是否意味着以后更需要算法优化，而不是工程优化？

江澈： 两者都需要。算法层面的重要问题，是系统怎样积累和学习经验，也就是今天讨论的自进化与元进化。但工程同样是 AI4AI 的重要优化对象。随着模型更大、用户更多、经验规模更高，系统工程的优化会变得更加必要。大厂的产品闭环中，算法和工程本来就是相互连接的环节。

14. 主观指标怎样避免 reward hacking？

问： 客观指标比较容易评测，主观指标怎样避免 reward hacking？

答： 这是尚未解决的问题。AI 给出的主观评价经常无法与人类主观判断完全对齐。

一种缓解方法，是人工设计能够跨任务使用的 Rubric，把主观目标拆成较明确的评价维度。但这只能缓解问题，不能说明主观评价已经解决。如何让评价器与人类偏好长期对齐，仍然非常值得研究。

15. RSI 是否就是能够持续复利的元进化？

问： RSI 是否可以理解为越改越好、能够持续复利的元进化？

答： 这是我的理解。一个关键判断是：为了完成改进所投入的算力或智能，是否小于后续由改进结果节约或产生的算力和智能。如果投入一份智能，能持续产生多于一份的后继智能，就形成了正向复利。

16. 评价器本身是否也需要进化？

问： 随着系统进化，原来的评价是否会变得不匹配？

答： 是的。进一步可以把 Agent 任务变成一个可学习的模拟模型，让世界模型和 Agent 相互交互、相互训练，形成双方轮流进化的结构。评价机制不能永久固定，否则它迟早会成为系统能力继续增长的瓶颈。

17. 小团队怎样规模化 Skill 和任务？

问： 资源有限时，怎样规模化元进化所需的 Skill 和任务？

答：如果目标是在通用 AI 上直接与大厂竞争，小团队很难在规模上取胜。但可以从某个高价值垂直领域开始，再逐渐向外扩张。

MLE 只是整个 AI 任务空间中的一小块。我们可以先把这一小块中的任务收集和构造得足够完整，再寻找与它相邻、可以复用当前能力的任务，逐步扩大任务分布。任务不一定全靠收集，也可以主动构造。

但需要注意，不能简单地说Loop is all you need。如果循环中没有经验积累和学习，只是反复修改，就像一直刷题却不做错题本，不会产生持续提升。有循环不等于有自进化；循环必须让过去真正改变未来。

18. RSI 是否只适合算力充足的玩家？

RSI 是否更适合算力充足的玩家？

如果指最终形态的 RSI，应该是的。系统要训练出更强的后继模型，仍然需要足够的算力。但对资源有限的研究者来说，并不需要一开始就追求通用 RSI，可以先在垂直、高价值、可验证的任务中研究自进化和元进化机制。
