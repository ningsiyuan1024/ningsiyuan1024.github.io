Harness 工程示例

1. 为客户会议做准备

任务：一位客户经理请智能体为明天与客户的会议准备一份简报，内容涵盖未解决的问题和议程草案。
harness 的作用：
  • 智能体通过电子邮件连接器，在该经理的收件箱中搜索与这位客户往来的邮件。
  • 权限设置允许它读取电子邮件，但不允许发送任何邮件。
  • 上下文管理只向模型提供最近三个月与该客户往来的邮件，而非整个收件箱。
  • 智能体循环会执行数轮搜索和阅读，模型则将找到的内容归纳为若干未解决的问题。
  • 随后，验证环节会检查简报中的每个问题是否都能对应到一封真实的电子邮件。
预期的结果：经理会收到一份一页纸的简报，其中每一点都可以追溯到来源邮件。

2. 更新月度销售报告

任务：一位运营主管请智能体用本月的数据更新月度销售报告。
harness 的作用：
  • 记忆功能会加载上个月会话中的笔记，包括报告的格式，以及该主管提出的将数字四舍五入到千位的要求。
  • 文件工具会打开团队共享云端硬盘上的销售电子表格。
  • 权限设置允许智能体编辑报告草稿，但不允许编辑源电子表格，因此原始数据不会被误改。
  • 验证环节会检查报告中的总计是否与电子表格一致。
预期的结果：报告以与上个月相同的格式交付，用户无需再次说明。

3. 整理共享收件箱

任务：一个支持团队请智能体按主题整理上午收到的请求，并为常见请求起草回复。
harness 的作用：
  • 智能体循环会逐封处理收件箱中的邮件。
  • 对于每封邮件，模型会选定一个主题标签，然后由 harness 通过电子邮件连接器添加该标签。
  • 在任务开始时，harness 会将团队已获批准的回复模板作为参考添加到上下文窗口中，让模型以模板为基础撰写每份草稿。
  • 一条审批规则会将每条回复保留为草稿，直到团队中有人审核并发送。
预期的结果：团队开始一天的工作时，请求已经分类完毕，回复也已在等待审核。

4. 修复网站中的错误

任务：一位开发者请编程智能体修复一个导致结账按钮无法正常工作的错误。
harness 的作用：
  • 智能体在沙盒中工作。沙盒是代码的隔离副本，智能体在其中所做的更改不会影响线上网站。
  • 代码工具让模型可以读取和编辑文件。
  • 每次更改后，验证环节都会运行项目的自动化测试。
  • 任何失败都会作为新信息反馈给模型。
预期的结果：智能体会不断调整修复方案，直到测试通过。随后，开发者会在更改上线前对其进行审查。
