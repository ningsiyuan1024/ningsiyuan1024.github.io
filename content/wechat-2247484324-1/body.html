一、评测的目标

• 对用户：Agent是不是好用、能不能稳定解决真实问题、能不能减少用户的认知负担与交互成本。

• 对业务：是不是提高了效率、是不是节省了成本、是不是达成了业务指标（比如转化率）。

• 对技术：能力边界在哪里（能做什么/不能做什么）、是否稳定、哪些方面需要优化。

二、指标体系

• 能力维度（能不能把事做完）


• 任务完成度：成功率（任务完成次数/总测试次数）、自动化率（自动化测试/人工测试）、任务闭环率（关键在于是否真正给出了可执行的结果，而非空谈）。

• 回答准确度：回答是否有幻觉、是否准确、人工评估与标准答案检测语义相似度。

• 技能覆盖度：所有设计的功能是不是都能有效触发和执行、工具调用是否成功、是否存在能力有但用不到的问题。

• 体验维度（好不好用）

• 对话质量：连贯性（能不能理解上下文，不出现答非所问）、逻辑性（推理是否清晰，步骤是否合理）、人性化（语气是否像“助手”）。

• 体验与性能：响应时间、交互轮次（是否可以通过一次性问用户多个相关的问题，减少对话轮次）、中断率（用户是否中途放弃对话）。

• 个性化与主动性：能不能记住用户偏好（长期/短期）、能不能主动补充信息或澄清问题、是否给出合理的下一步建议。

• 可靠和安全维度（可不可以放心用）


• 安全性：确保内容无害、没有偏见、信息严格保密。

• 稳定性：是否是7*24可以访问、使用？高峰期的响应时间是否达标？高并发下的表现如何？

• 可控性：出错时是否有纠错机制、是否支持人工兜底、是否可回放、可日志、可溯源。

• 业务与价值维度（值不值得继续投）

• 用户满意度

• 留存与使用频率

• 其他关键KPI，比如响应时间、问题解决率、人工接入率


三、评测方法

• 分层评测

• 单元测试：单工具、单技能是否正常。

• 组件测试：Tool + LLM, RAG + Reasoning, Memory + Planning。

• 集成测试：完整任务流程能否跑通，是否存在中间失败但未被捕获的情况。

• 人工评测：专家review，重点关注复杂、模糊、开放式任务。

• 线上A/B测试：不同版本的agent给不同人使用，看反馈。

• 测试集：一定要“真实又残忍”

• 标准测试集：覆盖主流程、高频任务，用于日常回归测试。

• 边缘测试集：模糊指令，不完整信息，经常容易出问题的地方。

• 红队测试集：专门用于安全测试的恶意、诱导性问题集。


四、评测落地建议

• 指标不要一次性全上，按阶段聚焦。

• 能力评测优先于体验评测。

• 离线评测 ≠ 真实效果，必须结合线上数据。

• 所有评测结果都应能反向指导Prompt / Tool / Agent设计。

Agent评测的核心不是“模型多强”，而是它是否在真实场景下，稳定、可控地创造价值。
