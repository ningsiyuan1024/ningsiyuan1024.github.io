最近发现和AI讨论时做决策树，可以把80%的烦恼都转化成方便执行的If-Else，节省决策时间还减少了很多焦虑情绪。

给非计算机背景的朋友们科普一下决策树，就是把一个复杂选择拆成一连串“如果……那么……”的问题，沿着不同答案逐步走到最合适的行动。下图是一个非常非常基础的示例。


这种呈现形式和前段时间火的Loop Engineering很像。人脑在思考时是多线程的，AI的线性文字表达对我们来说效率很低。所以我更喜欢我的AI给我一个决策树，几个字就能表达决策点，几条线就能解释背景框架。

这里整合了一些计算机学科的概念，来辅助日常决策，放在prompt/harness里都很好用：


选择与判断 → 决策树：把条件写成“如果—那么”，逐层排除，直到得到行动。

优先级混乱 → 优先队列：按重要性、紧迫性和收益排序，每次只处理队首。

任务太复杂 → 递归分解：把大问题拆成结构相同的小问题，直到每一步都能直接执行。

方案选择 → 动态规划：记录每一步的最优结果，组合成整体最优方案。

资源有限 → 背包问题：在时间、预算有限时，选择总价值最高的事项组合。

短期快速推进 → 贪心算法：每一步先选当前收益最大的动作，但警惕局部最优。

寻找最佳路径 → 图搜索：把人、资源和步骤看成节点，寻找成本最低的连接路径。

排查问题原因 → 二分查找：每次把可能范围砍掉一半，快速定位问题所在。

调试沟通冲突 → Debugging：区分事实、假设、情绪和触发条件，逐项验证真正故障点。

信息太多 → 哈希索引：给信息建立固定标签和入口，减少反复搜索。

持续学习 → 缓存机制：把高频使用的知识整理成模板、清单和快捷回复。

防止遗忘 → 数据库：重要信息不要依赖记忆，而要结构化记录并可检索。

多人协作 → 版本控制：保留修改记录、明确责任人，冲突时比较版本而非争论记忆。

意见分歧 → 分布式共识：先统一事实、目标和决策规则，再追求结论一致。

沟通失败 → 协议设计：事先约定术语、输入、输出、响应时间和异常处理方式。

减少误解 → 类型系统：明确一句话是在表达事实、观点、猜测、需求还是承诺。

建立边界 → 权限控制：不同的人只获得完成其职责所需的信息和决定权。

预防意外 → 异常处理：提前写出“如果失败怎么办”，为关键行动准备兜底方案。

应对风险 → 冗余与备份：重要资源、时间节点和关键人员都不要只有单点依赖。

处理高频请求 → 限流机制：规定响应窗口和容量上限，避免被外部需求持续打断。

排队与协调 → 消息队列：把请求统一收集、排序、逐个处理，而不是即时响应一切。

长期系统失控 → 技术债思维：临时方案可以使用，但必须记录未来要偿还的成本。

复盘因果 → 日志系统：记录关键时间、输入、行动和结果，用证据代替事后印象。

习惯养成 → 状态机：明确自己当前所处状态，以及进入下一状态需要满足的条件。

复杂流程设计 → 有限状态机：列出所有合法状态和转换，避免遗漏特殊情况。

组织分工 → 模块化：让每个人或流程只承担一种清晰职责，通过接口协作。

降低相互牵制 → 解耦：把强依赖关系改成标准化交接，减少一方变化导致全盘返工。

提炼共性 → 抽象：忽略无关细节，找到多个问题背后相同的结构。

把握细节 → 分层架构：先讨论目标，再讨论策略、流程和具体动作，避免层级混杂。

验证想法 → 单元测试：先用一个小场景检验假设，再扩大投入。

重要决策 → A/B 测试：条件允许时并行试两种方案，让结果而非争论决定选择。

识别隐患 → 对抗性测试：主动问“怎样才能让这个方案失败”，提前发现脆弱点。

面对不确定性 → 贝叶斯更新：先形成暂时判断，再根据新证据持续调整概率。

重复博弈 → 博弈论：不要只看一次输赢，要设计让长期合作更有利的规则。

他人反应难预测 → 仿真模拟：分别代入乐观、中性和悲观情境，预演可能结果。

需求不断变化 → 敏捷迭代：先交付最小可用版本，再根据反馈逐轮改进。

目标模糊 → 算法输入输出：先明确已知条件、限制条件和期望结果，再讨论方法。

选择框架困难 → 元算法：先判断问题属于选择、排序、搜索、分配、协作、预测还是纠错。
